# Data Dictionary

Fill this in as you finalise each CSV/table. One row per field.

## locations
| Field | Type | Description |
|---|---|---|
| location_id | text | Unique ID, e.g. L001 |
| name | text | Real place name, e.g. Balme Library |
| area | text | Campus zone, e.g. Legon |
| location_type | text | Library / Academic / Hostel / Clinic / ... |
| x_coord, y_coord | real | Latitude/longitude or local coordinate |

## roads
| Field | Type | Description |
|---|---|---|
| road_id | text | Unique ID, e.g. R001 |
| from_location_id, to_location_id | text | Foreign keys into locations |
| distance_km | real | Real or estimated distance |
| travel_time_min | real | Real or estimated travel time |
| condition_weight | real | >1.0 means slower/worse road condition |

## service_requests
| Field | Type | Description |
|---|---|---|
| request_id | text | Unique ID, e.g. Q001 |
| source_location_id, destination_location_id | text | Foreign keys into locations |
| category | text | Medical / IT Support / Maintenance / Security / Shuttle / Document |
| urgency | int | 1 (low) to 5 (high) |
| time_submitted, deadline | text (ISO-8601) | e.g. 2026-07-01T08:15 |
| status | text | NEW / IN_PROGRESS / DONE / CANCELLED |

## resources
| Field | Type | Description |
|---|---|---|
| resource_id | text | Unique ID, e.g. V001 |
| resource_type | text | Van / Rider / Technician / ... |
| home_location_id | text | Foreign key into locations |
| capacity | int | How many requests it can carry/handle at once |
| availability_status | text | AVAILABLE / BUSY / OFFLINE |

## algorithm_runs
| Field | Type | Description |
|---|---|---|
| run_id | text | Unique ID |
| algorithm_name | text | e.g. "binary_search", "dijkstra" |
| input_size | int | n for that run |
| time_ns | int | Average of 3 trials |
| memory_kb | int | Optional |
| date_run | text | ISO-8601 date |

## Index-number-derived parameters

numbers (Section 2.iii). All three are implemented and computed (not
hand-entered) in `src/main/java/com/campus/optimizer/IndexParams.java` —
keep both in sync if the roster or formulas change.

1. **random_seed** = INDEX_NUMBER mod 10000, where INDEX_NUMBER = 22128192
   (Chris Nana Opoku) → 22128192 mod 10000 = **8192**. Used in
   `scripts/generate_requests_resources.py` to seed `random.seed()` before
   generating `service_requests_full.csv` and `resources_full.csv`.
2. **priority_weight** = (sum of digits of INDEX_NUMBER) mod 5 + 1, using the

3. **hash_table_size** = nearest prime to the average team index number.

   finding the nearest prime → nearest prime to 413 is **409**. This is the
   default bucket count the hash-table owner should pass into
   `MyHashTable`'s constructor before running the load-factor experiment.

## Dataset provenance (evidence note)

- **Locations (50):** real University of Ghana, Legon campus landmarks —
  halls of residence, academic departments, administrative buildings,
  commercial and religious sites — with coordinates looked up individually.
  No personal data involved.
- **Roads (100):** distances computed with the Haversine formula from each
  location's real coordinates (`scripts/generate_roads.py`). Connectivity
  is inferred by proximity: a minimum spanning tree guarantees every
  location is reachable, then nearest-neighbour edges are added on top so
  close-by buildings have a direct path. Travel time assumes an 18 km/h
  average campus vehicle speed; condition_weight is slightly worse for
  roads touching a campus entrance/gate.
- **Service requests (300) and resources (30):** intentionally synthetic,
  generated by `scripts/generate_requests_resources.py` with a random seed
  derived from a team member's index number (see above). Categories,
  urgency distribution and SLA deadlines are modelled on a realistic campus
  service load.
